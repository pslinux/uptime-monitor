# Uptime-Monitor 需求文档

> 版本：v1.0.0 ｜ 编制日期：2026-08-18 ｜ 状态：已评审

---

## 1. 项目概述

### 1.1 背景

现有监控方案中，Uptime Kuma 不原生支持 Oracle 数据库（1521 端口）的健康检查。此前使用 Shell 脚本（`monitor_oracle.sh`）调用 `sqlplus` 实现，但存在依赖脚本解释器、配置与代码耦合、跨平台分发不便等问题。

本项目使用 **Go 语言**重新实现该监控程序，提供独立配置、灵活驱动、可编译打包成 Linux 单二进制、可迭代演进的健康监控能力。

### 1.2 目标

| 编号 | 目标 |
|------|------|
| G1 | 周期性连接 Oracle，执行 `SELECT 1 FROM DUAL` 验证数据库可用性 |
| G2 | 将检查结果实时上报到 Uptime Kuma 的 Push 接口（up/down） |
| G3 | 配置参数独立存放，支持环境变量覆盖，避免改代码 |
| G4 | 可编译为 Linux 静态二进制，一键部署，无解释器依赖 |
| G5 | 支持多种数据库驱动实现，便于扩展 |

### 1.3 非目标

- 不实现 Web 界面（由 Uptime Kuma 承担展示与通知）
- 不实现完整的数据库性能监控（表空间/SQL 性能等后续迭代）

## 2. 用户与场景

### 2.1 目标用户

- 运维工程师：部署并配置监控程序
- 监控平台：Uptime Kuma（接收 Push 上报并展示/告警）

### 2.2 典型场景

1. 运维在服务器上部署程序，填入数据库与 Push 地址
2. 程序每 60 秒检查一次 Oracle，正常则上报 `up`
3. 数据库宕机/连接失败则上报 `down` 并附错误信息
4. Uptime Kuma 超时未收到上报时自动判定宕机

## 3. 功能需求

### FR-1 配置管理

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-1.1 | 支持 YAML 配置文件，独立于代码存放 | P0 |
| FR-1.2 | 支持环境变量覆盖（`UM_DB_HOST`、`UM_DB_PASSWORD`、`UM_PUSH_URL` 等） | P0 |
| FR-1.3 | 配置缺失/非法时给出明确错误并退出 | P0 |
| FR-1.4 | 敏感字段（密码）不强制明文写在配置文件 | P0 |

### FR-2 数据库健康检查

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-2.1 | 周期执行健康检查 SQL（默认 `SELECT 1 FROM DUAL`） | P0 |
| FR-2.2 | 支持连接超时与 SQL 超时，避免检查卡死 | P0 |
| FR-2.3 | 支持 `sqlplus` 驱动（调用外部客户端） | P0 |
| FR-2.4 | 支持 `godror` 原生驱动（database/sql） | P1 |
| FR-2.5 | 检查失败支持重试（V3） | P1 |

### FR-3 状态上报

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-3.1 | 检查正常上报 `status=up` | P0 |
| FR-3.2 | 检查失败上报 `status=down` 并附错误信息 | P0 |
| FR-3.3 | 上报携带 `ping`（检查耗时，毫秒） | P1 |
| FR-3.4 | 上报失败记录日志 | P0 |

### FR-4 日志

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-4.1 | 支持日志级别（debug/info/warn/error） | P0 |
| FR-4.2 | 支持输出到文件或 stdout | P0 |
| FR-4.3 | 日志文件大小超过上限自动轮转（V3） | P1 |

### FR-5 运行与运维

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-5.1 | 支持优雅停机（SIGINT/SIGTERM） | P0 |
| FR-5.2 | 提供 systemd 部署单元 | P0 |
| FR-5.3 | 提供 Linux 打包构建脚本 | P0 |
| FR-5.4 | 支持多架构交叉编译（V3） | P1 |
| FR-5.5 | 核心模块单元测试（V3） | P1 |

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 性能 | 单次检查耗时 < 3 秒（正常网络）；检查频率可配置（默认 60 秒） |
| 可靠性 | 数据库瞬时失败自动重试；上报失败不影响主循环 |
| 安全性 | 数据库账号建议最小权限只读；密码支持环境变量注入 |
| 兼容性 | 目标平台 Linux amd64/arm64；Go >= 1.21 |
| 可维护性 | 分层结构（config/db/notifier/logger），接口化便于替换 |

## 5. 技术方案

### 5.1 技术选型

| 项目 | 选型 | 说明 |
|------|------|------|
| 语言 | Go 1.21 | 静态编译、并发安全、跨平台 |
| 配置 | YAML（`gopkg.in/yaml.v3`） | 结构清晰 |
| Oracle 驱动 | sqlplus / godror | 双驱动，见 5.2 |
| HTTP 上报 | `net/http` 标准库 | 无额外依赖 |
| 日志 | 自研轻量 logger | 支持文件与轮转 |

### 5.2 双驱动设计

```
                    +---------------------+
                    |   DBDriver 接口      |
                    +---------------------+
                        |             |
              +---------+             +---------+
              | sqlplus驱动          | godror驱动   |
              | (调外部sqlplus)       | (原生database/sql)|
              | 静态编译,部署简单       | 需CGO+InstantClient|
              +---------------------+  +----------------+
```

| 驱动 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| sqlplus | 纯静态编译、无 CGO、打包简单 | 依赖目标机有 sqlplus | 快速部署 |
| godror | 程序内连接、无需 sqlplus | 需 CGO + Instant Client | 原生集成 |
